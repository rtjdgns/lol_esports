# 사전조사 프롬프트

아래 전체를 새 대화창(웹 검색이 가능한 곳 또는 Claude Code)에 붙여넣는다.

---

LoL e스포츠 일정·순위 경우의 수 앱을 만들기 위한 사전조사를 해줘. 오늘 날짜를 기준으로 최신 정보를 검색하고, 각 항목을 아래 형식으로 정리해.

## 공통 규칙
- 모든 결론에 출처 URL과 정보의 날짜를 붙인다.
- 확실성을 "확인됨 / 추정 / 미확인" 중 하나로 표시한다. 출처가 없으면 "미확인"이다.
- 공식 문서와 1차 출처를 우선한다. 블로그·커뮤니티 글은 보조 근거로만 쓰고 그렇다고 표시한다.
- 짧게 쓴다. 불필요한 서론과 공손한 표현은 생략한다.
- 모르는 것은 모른다고 쓴다. 추측으로 채우지 않는다.

## 출력 형식
항목별로 표 하나: 질문 / 결론 / 근거 URL / 확실성 / 다음에 직접 확인할 것.
마지막에 "아직 모르는 것" 목록과 "내가 직접 해봐야 할 것" 목록을 따로 둔다.

## 조사 항목

### A. Riot lolesports API
1. API 키 헤더가 필요한가. 키는 어떻게 얻는가 (공개 키인지, 신청이 필요한지).
2. getSchedule, getLive, getStandings, getEventDetails 등 엔드포인트별 요청 파라미터와 응답 필드.
3. 시리즈 스코어, Bo 형식, 경기 상태(예정/진행/종료), 대회 단계(정규/플레이오프/스테이지) 필드가 있는가.
4. 팀·로스터·선수 정보 엔드포인트가 지금도 동작하는가.
5. 호출 제한(rate limit)이 알려져 있는가.
6. 비공식 API 사용에 대한 Riot의 정책·약관은 무엇인가 (Riot 개발자 정책, e스포츠 데이터 관련).
7. 이 API를 쓰는 오픈소스 프로젝트의 최근 상태와 깨진 사례가 있는가.

### B. 보조 데이터 소스
1. PandaScore: 무료 플랜 범위, 호출 제한, LoL 일정·시리즈 스코어 제공 여부, 상업적 이용 조건.
2. Leaguepedia(Cargo API): 접근 방식, 로스터·이적 데이터 제공 범위, 이용 조건.
3. 그 밖에 LoL 일정·결과를 제공하는 공개 API가 있는가 (Oracle's Elixir 등 포함).

### C. 대회 규칙 (순위·대진 경우의 수 입력)
1. 올해 월즈(롤드컵) 포맷: 스테이지 구조, 팀 수, 진출 조건, 시드 배정, 대진 방식, 일정. 현재 진행 상황.
2. 월즈의 순위 산정 방식과 타이브레이커 규칙 (공식 규정집 우선).
3. 올해 LCK 포맷과 순위 산정·타이브레이커 규칙, 시즌 종료 여부와 최종 일정.
4. 공식 규정집 문서의 위치와 갱신 주기.
5. 규칙이 해마다 어떻게 바뀌어 왔는지 최근 3년 변경점.

### D. 비정형 데이터 수집 조건
1. 이적·로스터 변경의 공식 발표 채널 (LCK, 팀 공식 채널) 목록과 형식.
2. 국내 e스포츠 언론사의 RSS 제공 여부, 기사 요약·링크 저장의 저작권·이용약관 범위.
3. 선발 라인업이 경기 전에 공식 데이터로 제공되는지, 보통 언제 공개되는지.
4. 로스터 등록 기간(LCK, 국제대회)과 이적 시장 일정.

### E. 알림·배포 인프라
1. 개인 프로젝트 규모에서 쓸 수 있는 푸시 알림 방식 비교: 웹 푸시, FCM, APNs, 텔레그램/디스코드 봇. 각각 무료 범위와 제약.
2. iOS Live Activities 구현 요건과 개인 개발자 제약.
3. ICS 캘린더 구독 피드 구현 시 알려진 주의점 (갱신 주기, 클라이언트별 동작 차이).

### F. 경쟁 서비스 재확인
1. 이스코어, Riftly, Strafe, Sofascore, 닥지지, 네이버 e스포츠가 "시리즈 상황 문구"(예: 2:1, 1승 남음)와 "순위 경우의 수"를 제공하는지. 앱 스토어 설명, 스크린샷, 리뷰 근거로 확인한다. 직접 써봐야 알 수 있는 것은 "내가 직접 해봐야 할 것"에 넣는다.
2. 같은 기능을 제공하는 LoL 전용 서비스가 새로 나왔는지.

마지막에 위 조사 결과가 프로젝트 계획(통합 일정, 시리즈 상황 문구, 알림, 순위·대진 경우의 수)에 주는 영향을 5줄 이내로 정리해.
